# 구글 캘린더 일정 잡기

Tyler(tyler@zigbang.com, Asia/Seoul)의 캘린더에 일정을 만든다. 두 가지 모드가 있다:

| | **회의** | **개인일정** |
|---|---|---|
| 구분 기준 | 참석자·회의실이 있음 | 참석자 없음 ("병원", "개인 약속", "혼자 작업" 등) |
| 참석자/회의실 | 이름 해석 + freebusy 확인 + 초대 | 없음 |
| 공개 범위 기본 | `visibility: "public"` | `visibility: "private"` |
| 초대 메일 | Tyler가 발송/미발송 선택 | 해당 없음 (`sendUpdates: "none"`) |

어느 쪽인지 애매하면 (참석자 언급이 없는데 회의 같은 제목) Tyler에게 확인한다.

## 개인일정 절차 (간단)

1. `get-current-time`으로 현재 시각 확인 후 요청의 날짜·시간 해석 (길이 미지정 시 기본 1시간).
2. Tyler 본인 캘린더(primary)만 freebusy로 충돌 확인 — 겹치면 알리고 진행 여부를 묻는다.
3. `create-event`: primary, `visibility: "private"`(기본, 공개 요청 시만 "public"), `sendUpdates: "none"`, 참석자·location 없음(장소 언급이 있으면 location에 기입).
4. 제목 / 일시 / 링크 보고.

## 회의 절차

### 0. 현재 시각 확인
반드시 `get-current-time`을 먼저 호출한다. "내일", "다음주 화요일" 같은 상대 날짜를 여기 기준으로 해석한다.

### 1. 요청 파싱
- **제목**: 명시 없으면 "○○ 논의", "스마트홈 ○○ 회의"처럼 짧게 생성.
- **시간**: 명시된 시각이 있으면 그대로. 길이 미지정 시 **기본 1시간**.
- **참석자**: 이름 → 이메일 변환. 먼저 `references/people.md`에서 찾고, 없으면 `search-events`로 그 이름이 붙은 과거 이벤트를 찾아 attendees에서 이메일을 확인한다 (직방 이메일은 대개 영어이름@zigbang.com). 그래도 못 찾으면 Tyler에게 물어본다. 확인된 새 인물은 people.md에 추가한다.
- **회의실**: `references/rooms.md`에서 이름·리소스 이메일·수용 인원을 찾는다. 표에 없으면 rooms.md 하단의 발견 절차를 따른다.
- **초대 메일 발송 여부**: 생성 직전에 **항상 Tyler에게 선택받는다** (AskUserQuestion 사용).
  - **발송**: 참석자에게 초대 메일이 간다 → `sendUpdates: "all"`
  - **미발송**: 캘린더에만 잡히고 메일은 안 감 → `sendUpdates: "none"`
  - 단, 요청에 이미 명시되어 있으면 ("메일 보내지 마", "초대장 보내줘") 묻지 않고 그대로 따른다.
- **공개 범위**: **기본 공개** → `visibility: "public"`. "비공개로" 지시가 있을 때만 `"private"`.

### 2. 참석자·회의실 일정 확인 (필수)
`get-freebusy`로 **모든 참석자 이메일 + 회의실 리소스 이메일**을 한 번에 조회한다.

- **시간이 지정된 경우**: 그 시간대 충돌 여부만 확인.
  - 전원+회의실이 비어 있으면 → 바로 생성.
  - 누군가 겹치면 → 만들지 말고, 누가 언제 겹치는지 보고하고 근처의 공통 빈 시간 2~3개를 대안으로 제시한 뒤 Tyler의 선택을 기다린다. (Tyler가 "그냥 잡아"라고 하면 충돌 무시하고 생성.)
- **시간이 안 정해진 경우** (예: "내일 중으로", "이번주에"): 해당 범위를 freebusy로 조회해 업무시간(평일 09:00–18:00, 점심 12:00–13:00 피함) 내 공통 빈 슬롯 2~3개를 찾아 제안하고 선택받는다.

회의실만 겹치는 경우는 rooms.md에서 같은 시간대에 빈 다른 회의실(인원수 충족)을 찾아 대체 제안한다.

### 3. 이벤트 생성
`create-event`로 primary 캘린더에 생성한다:

- `summary`: 제목
- `start`/`end`: `2026-07-17T15:00:00` 형식 (Asia/Seoul, timeZone 필드 지정)
- `attendees`: 참석자 이메일들 + **회의실 리소스 이메일** (Tyler 본인은 organizer라 넣지 않아도 됨)
- `location`: 회의실 이름 (rooms.md 표기 그대로)
- `sendUpdates`: 1단계에서 Tyler가 선택한 값 (`"all"` 또는 `"none"`)
- `visibility`: `"public"` (기본) — 비공개 요청 시에만 `"private"`
- 화상 참석자가 있거나 요청 시 `conferenceData.createRequest`로 Google Meet 추가 (requestId는 아무 고유 문자열)

### 4. 결과 보고
생성 후 요약해서 보고: 제목 / 일시 / 참석자 / 회의실 / 초대 메일 발송 여부 / 캘린더 링크(htmlLink).

## 주의

- **일정 확인 없이 바로 만들지 않는다** — freebusy 체크는 항상 선행.
- 참석자 이메일이 불확실한 채로 초대를 보내지 않는다 (오발송 방지).
- 이벤트 수정·삭제 요청이면 `update-event`/`delete-event`를 쓰되, 삭제는 Tyler에게 한 번 확인.
- freebusy는 상대가 캘린더를 공유하지 않으면 빈 결과가 나올 수 있다 — "확인 불가"로 표시하고 진행 여부를 묻는다.

## 참조 파일

- `references/rooms.md` — 회의실 이름 ↔ 리소스 이메일 ↔ 수용 인원
- `references/people.md` — 임직원 이름 ↔ 이메일 명부 (새 인물 확인되면 추가)
